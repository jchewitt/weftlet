# Remaining 1.0 work

This queue tracks implementation increments for [B1–B6](PRE-1.0-BASELINE.md), whose acceptance
boundaries remain canonical. It supersedes the earlier instruction to rerun the private consumer
immediately after every patch. On 2026-10-28 the maintainer reported that the filename issue was
believed to be TradePilot's main blocker and requested the next live test after a new candidate.
That report is not a recorded private hydration/repeat or product-usefulness pass.

Work in small reviewed increments. Keep a minor candidate version PR open while these changes
accumulate; publish the next candidate when the agreed scope is ready, then run live acceptance.
Do not publish official 1.0 solely because deterministic tests or graph hydration succeed.

Maintainer disposition, 2026-11-02: publish **0.7.0** for TradePilot acceptance now. The optional
B3b proposal feature's live validation is **tentative and deferred**, not a publication blocker
for this candidate. Prior consumer Codex hydration remains evidence for the established extraction
flow; it does not validate the new proposal operation. No further feature milestone is scheduled
before this candidate. B6b and the explicit official 1.0 decision remain open.

Consumer blocker, 2026-11-02: 0.7.0's richer code graph exceeded Node's whole-string limit before
strict SHACL/publication. [ADR 040](ADR-040-bounded-graph-io.md) tracks the hashing, persistence,
RDF/query and bounded-validation patch. Its public large-corpus lifecycle and hosted Linux/Windows checks
pass; patch publication and private acceptance remain separate steps. No 1.0 approval is implied.

Consumer follow-up: **0.7.1 is published**. The maintainer reports successful strict hydration,
persistence/reload and unchanged repeat of 561,777 facts / 174,710 nodes with all 18 cached
artifacts preserved. That capacity blocker is resolved in the reported run. B6b remains open:
known direct paths and specific worker `references`/`consumes` assertions were displaced outside
fixed retrieval budgets. [ADR 041](ADR-041-bounded-relationship-retrieval.md) tracks the bounded
query-order patch and its public regression; no extraction refresh is needed for that patch.

and calls surface at the original budget. Keep **one indirect-ranking ticket open**: retrieve
