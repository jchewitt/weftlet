## 0.11.0 storage release for 1.0 evaluation

Both packages were [published from the versioned commit](https://github.com/jchewitt/weftlet/actions/runs/44618981512).

Upgrade every process sharing a cache before enabling [coordination](guides/CACHE-COORDINATION.md)
or [compact writes](guides/COMPACT-SNAPSHOTS.md). To adopt a history target in an existing
cache, start with the [migration procedure](guides/CACHE-HISTORY.md#upgrade-a-cache-that-is-already-over-target).
Review one plan before scheduling cleanup, and enable companion-index retirement explicitly
if you want to reclaim a superseded generation’s verified SCIP file. Keep the first consumer
measurement read-only until the operator reviews the policy and selected bytes.

## 0.10.0 release scope

The integrated release includes:

- Independent Claude Code and initial OpenCode API extraction and mapping
  proposals. Neither requires Codex; live authentication/model quality and actual
  client loading retain their separately recorded qualification limits.
- Automatic project skills, bulk governing-source configuration, MCP registration
  and verification, GitHub CI scaffolding, and optional provider-assisted setup
  with a reviewed change plan.
- Verified snapshot export/import for CI-to-local delivery and a complete public
  tutorial using fresh installed packages.
- Independent clean comparisons with temporary output and compact receipts,
  read-only cache inventory/size profiling, and declared retention plan/check
  commands. Retention reviews never remove data; coordinated pruning, configurable
  history retention and compact storage remain subsequent milestones.

Both 0.10.0 packages are published on npm from
`402c9f898330fff79f7ca8fad2f1bae1dcbd4ec0`; downloaded archives match their reviewed
SHA-512 values and exact prepared bytes. See the [validation record](VALIDATION.md)
for publication/recovery evidence and the separate docs-site delivery status.
Consumer acceptance and live-provider qualification remain distinct from publication.

Architecture-only packaging and the 2.0 hosted review/AI service remain separate
plans. The [work queue](1.0-WORK-QUEUE.md) records remaining 1.0 storage and
consumer-acceptance work; this minor release is not a complete 1.0 claim.

## Before upgrading

Read the target changelog for refresh requirements. Keep matching package versions,
retain old snapshots/artifacts, preview work with `hydrate --plan`, and approve any
new model cost before hydration. Query-only improvements may need only new query
pagination; extraction/identity changes can require a new graph and semantic work.
Historical evidence must remain labeled historical. Do not edit cached assertions
or weaken validation to make an old graph pass a newer contract.
